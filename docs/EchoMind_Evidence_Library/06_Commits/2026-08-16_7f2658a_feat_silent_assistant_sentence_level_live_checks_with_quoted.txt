    feat(silent-assistant): sentence-level live checks with quoted proof, record pull, scenarios
    
    Rebuilds the Silent Assistant (live transcript + boardroom) so every spoken
    sentence is tagged, verified against the sources with an exact quote as
    proof, and personal details pull the person's records — with behaviour
    selected per scenario (customer_care / legal / banking / general, or auto).
    
    Design came from a 4-auditor + 3-design + judge workflow; the build reuses
    the chat RAG stack (hybrid retrieve + CE rerank) rather than the old dense-
    only paragraph analyzer.
    
    Backend — new package backend/app/silent_assistant/
    - profiles.py: scenario profiles as data (roles, entity kinds, record
      targets, tag vocab with proof rules, domain rules, prompt rules, cues),
      suggest_scenario() detector.
    - entities.py: spoken-number normalizer ("A T four four eight two one" ->
      "A T 44821", "one hundred fifty dollars" -> "150 dollars", "seventeen of
      twenty twenty four" -> "17 of 2024") + regex extraction of person / account /
      policy / order / ticket / case / phone / email / dob / amount / date /
      clause / statute / org, with lookup variants.
    - state.py: per-session window, entities, subjects (candidate/confirmed,
      supersede weak name-only candidates), records, reference resolution.
    - retrieval.py: retrieve_for_claim (hybrid + CE, namespace fallback,
      evidence sentences ranked globally by overlap + CE rank), lookup_records
      (exact SQLite substring -> BM25 -> semantic -> CE; quotes must literally
      contain the identifier), legal related-case hop, reused-record linking.
    - verifier.py: ONE batched LLM call per 1-4 sentences that may only cite
      E#/R# evidence ids we supplied (quotes exact by construction); tag proof
      rules; claim/evidence grounding guard with re-cite; verdict/tag floors;
      programmatic commitment/question/action-item/record-found tags; TTS
      phrase templates.
    - service.py: T0 filler / T1 entities+records / T2 retrieval gate /
      T3 verify tiers, persistence, check_turns() for boardroom.
    
    Live pipeline (transcribe/)
    - session_state.py: sentence tracking with char offsets; STT chunk-boundary
      fragments coalesced (dangling-end / continuation-start rules, lookahead
      hold, mid-period cleanup); force_commit / close_paragraph_now.
    - ws.py: sentence enqueue + 1.2 s debounced batch (<=4, global LLM sem),
      idle loop with silent-chunk STT flush (VAD drops silence, so lookahead
      tokens only surfaced on the next speech), speaker turns as ordered PCM
      markers that flush+reset the stream, `session`/`warning` acks, new
      inbound speaker/scenario/subject, rich `segment` (role, sentences[]),
      superset `analysis` payload (legacy label kept), entity/subject/record/
      scenario_suggest events, namespaced transcript auto-store.
    - analyzer.py: analyze_segment() kept as a compat wrapper over the engine.
    - PROTOCOL.md documents the WS/REST contract.
    
    RAG (additive): advanced.retrieve_reranked()/ce_context_relevant() (rerank
    the WHOLE fused pool — BM25 #1 sat at fused pos 17), EvidenceSentence
    provenance (chunk_id/doc_id/doc_title), index.search_chunks_exact(),
    namespaced add_text/kb_add_text.
    
    Routes/DB: GET /transcribe/scenarios, GET /transcripts/{id}/assistant,
    PATCH /boardroom/sessions/{id}/speakers; boardroom analyse_meeting runs
    check_turns and the PDF gains "Statement checks with evidence" +
    "Records pulled"; additive schema (transcript_analysis widened,
    transcript_segments, assistant_entities/subjects/records).
    
    Frontend: ScenarioPicker (start modal tiles + session pill), RoleToggle
    (Alt+1/Alt+2), SubjectCard (Confirm / Not them), RecordPanel (grouped
    records with quotes, Open p.N, Copy), ActionsPanel, TagChip, ProofPopover,
    AssistantSidebar (Records | Checks | Actions with badges; mobile sheet),
    TranscriptSentences (per-sentence role chip, status glyph, inline tags,
    hover proof); AnalysisPanel/Modal evidence-first; history detail loads the
    assistant data and highlights checked sentences; hook handles the v2
    protocol and persists the scenario choice.
    
    Verified live (synthesized speech -> WS -> Nemotron -> checks, seed KB):
    28-29/36 scripted expectations across the four scenarios; the misses are
    STT mishearings. Median check latency ~1.2 s after the words end.
